## Summary

API backend em FastAPI para gerenciar agendamentos de barbearia. Cadastra clientes, barbeiros e serviços, mantém a disponibilidade semanal de cada barbeiro e cria agendamentos sem conflito de horário (409 para sobreposição, 422 para fora da disponibilidade ou no passado). Cada agendamento criado dispara uma confirmação de e-mail simulada, registrada no log, sem bloquear a resposta. O contrato é documentado em OpenAPI, então a API serve de base para um front-end web ou mobile. Projeto de estudo/portfólio, com SQLite local e sem autenticação.

## Lessons Learned

### Process

- Os agentes do manifesto do DESIGN (`@fastapi-developer`, `@python-developer`, `@test-generator`, `@code-documenter`) não foram usados: o build foi feito diretamente. O `fastapi-developer` foi criado no meio do fluxo e só apareceu como tipo disponível depois do build. Próxima vez: criar o agente antes do `/design` ou registrar no DESIGN que o build será direto, em vez de atribuir agentes que não serão invocados.
- O brainstorm entregou quase tudo que o Define precisava, então o `/define` não fez nenhuma pergunta nova. Funcionou porque o BRAINSTORM já trazia rascunho de problema, usuários, critérios e escopo fora.
- Quando o usuário escolhe, numa pergunta de múltipla escolha, critérios que omitem requisitos funcionais da descrição original (aqui, o 409 e o e-mail simulado), é melhor mantê-los e avisar explicitamente do que descartá-los. Isso foi sinalizado no brainstorm e confirmado no Define.

### Technical

- Os testes em memória (`StaticPool`) não exercitam o `BEGIN IMMEDIATE`. A garantia contra corrida só foi confirmada rodando 12 threads contra um banco em arquivo (1 × 201, 11 × 409). Essa verificação ficou num script descartável, fora da suíte; vale transformá-la em teste de integração.
- Injetar o relógio (`get_agora`) e o notificador por `Depends`, e trocá-los com `dependency_overrides`, deixou os 75 testes determinísticos, com datas fixas em 2030, sem biblioteca de congelar tempo.
- Mapear exceções de domínio para HTTP em uma única tabela em `main.py` manteve os services livres de FastAPI e permitiu 100% de cobertura do serviço de agendamento sem subir HTTP.
- Colocar o `BEGIN IMMEDIATE` no engine faz também as requisições só de leitura disputarem o lock de escrita no SQLite. É aceitável no MVP, mas é um custo a revisitar se houver carga.

### Communication

- Deixar a granularidade dos slots (A-003) e o texto do e-mail (A-006) como suposições do DEFINE e fechá-los no DESIGN evitou perguntas de baixo valor ao usuário e não gerou retrabalho.
- O DESIGN falou em "CRUD básico" enquanto o DEFINE pedia "cadastrar e consultar". O build seguiu o DEFINE e registrou o desvio. Próxima vez: alinhar o vocabulário dos dois documentos para a ambiguidade não chegar ao build.

### Tools & Libraries

- `ruff` achou um import não usado e linhas longas logo na primeira passada; `ruff check .` também varreu a pasta `.claude/skills/`, que não é do projeto. Restringir o lint aos diretórios do projeto desde o início evita ruído.
- O Starlette instalado marca `httpx` como obsoleto no `TestClient`; `httpx2` remove o aviso. Vale conferir avisos de depreciação na primeira execução dos testes.
- `pytest-cov` com `--cov=app.services.agendamento_service --cov-fail-under=85` transformou a meta de cobertura do DEFINE em um comando verificável.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Testes | Transformar a verificação de concorrência (12 threads, banco em arquivo) em teste de integração com marcador `integration` |
| Notificação | Implementar um `Notificador` SMTP real atrás do mesmo Protocol, com retentativa, e mascarar dados pessoais no log |
| Segurança | Adicionar autenticação JWT e papéis (cliente, barbeiro, admin); hoje qualquer chamador cria e cancela agendamentos |
| Banco | Ao migrar para PostgreSQL, trocar `BEGIN IMMEDIATE` por `SELECT ... FOR UPDATE` ou constraint de exclusão e adotar Alembic |
| Agenda | Suportar folgas e feriados por data, combos de serviços e fusos horários, que hoje estão fora do escopo |
| Desempenho | Se houver carga, aplicar `BEGIN IMMEDIATE` só nas rotas de escrita |
| Processo | Validar o README numa máquina limpa e decidir, antes do `/design`, se o build delegará aos agentes do manifesto |
